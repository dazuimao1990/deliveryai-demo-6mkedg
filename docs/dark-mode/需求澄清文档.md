# 需求澄清文档：黑夜模式（Dark Mode）

## 1. 需求与目标

### 一句话需求
在沸点火锅点单 Demo 应用中增加黑夜模式主题切换能力，使门店顾客和店员在夜间或弱光环境下能够切换至深色界面主题，减少屏幕亮光对眼睛的刺激，同时保持品牌视觉一致性和功能完整性。

### 背景
- 当前应用为单一浅色主题，所有界面元素使用 rice/charcoal/chili 色系硬编码在 JSX 中，Tailwind 未配置 `darkMode`，无 `dark:` 变体。
- 餐饮场景中，晚间用餐高峰时段顾客在弱光环境下使用点单界面，浅色背景的高亮度屏幕对眼睛刺激明显。
- 设计系统已提供完整的暗色 token 方案（`tokens.dark.json` / `variables.dark.css`），包含暗色背景、文字、边框、填充色等完整色阶，可直接作为黑夜模式的色彩基准。
- 已有「老人模式」作为先例（`useElderlyMode` hook，通过 localStorage 持久化 + html class 切换），黑夜模式可采用相同架构。

### 目标与成功标准
- 目标：用户可在顶栏一键切换黑夜模式，切换后所有界面元素适配深色主题。
- 目标：黑夜模式偏好持久化，刷新页面后保持用户选择。
- 成功标准：切换黑夜模式后，所有视图（首页、欢迎页、菜单、订单、结账页）的背景、文字、卡片、按钮、弹窗等元素均呈现深色主题，无明显的浅色残留或对比度不足问题。

## 2. 范围与业务规则

### 范围
- 做什么：
  - 在 TopBar 新增黑夜模式切换按钮（月亮/太阳图标）。
  - 启用 Tailwind `darkMode: 'class'` 配置，为所有视图组件添加 `dark:` 变体样式。
  - 新建 `useDarkMode` hook，管理黑夜模式状态（localStorage 持久化 + html class 切换）。
  - 在 `index.html` 内联脚本中预置黑夜模式初始化，避免页面加载时的主题闪烁（FOUC）。
  - 新增 i18n 文案（中/英）用于黑夜模式切换的 aria-label。
- 不做什么：
  - 不做跟随系统偏好（`prefers-color-scheme`）的自动模式——本次仅支持用户手动切换。
  - 不做主题定制市场或自定义颜色。
  - 不修改 `server/` 目录。
  - 不引入后端 API 或新的 UI 库。
  - 不改变现有功能逻辑和交互流程。

### 核心业务规则
- 黑夜模式默认关闭，首次进入应用为浅色主题。
- 用户切换黑夜模式后，偏好存储在 `localStorage`（key: `dark-mode`），刷新后保持。
- 黑夜模式与老人模式可同时启用，互不冲突（两个独立的 html class：`dark` 和 `elderly`）。
- 切换主题时全局有 250ms 平滑过渡（复用现有 `index.css` 过渡规则）。
- 黑夜模式影响所有视图，包括 HomeView（桌台绑定页）、WelcomeView、MenuView、OrderView、CheckoutView、TopBar、CartPanel、ServiceSheet、DemoConsole 及所有 Dialog 弹窗。

### 边界与异常
- localStorage 不可用时降级为内存态，不报错不阻塞（与老人模式一致）。
- 黑夜模式下图片资源保持原样不做滤镜处理（菜品图片在深色背景上仍需保持食欲感）。
- 黑夜模式下 `paper-noise` 纹理背景需适配深色（降低噪点透明度或调整色值）。

## 3. 用户与场景（概要）

- 目标用户：门店顾客（堂点）、店员（履约演示）
- 使用场景：晚间或弱光环境下使用点单应用，浅色界面亮度过高刺眼
- 关键路径概要：用户进入应用 → 点击顶栏黑夜模式按钮 → 界面切换为深色主题 → 后续操作均在深色主题下进行 → 偏好持久化
